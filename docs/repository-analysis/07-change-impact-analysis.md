## Dependency concentration and blast radius

`src.pricing` is the only application module imported by another application module. `room_subtotal` feeds `calculate_quote`, which feeds `create_quote`: changing its result changes all three response values transitively. `create_quote` has three distinct direct test-method callers; `preview_invoice` has two. These are small static counts, not evidence of deployment traffic. See [fan-in table](04-function-call-graph.md).

No database/network single point of failure or distributed bottleneck exists in the inspected source. As a logical dependency, quote generation relies on pricing to complete and provide the expected keys. Invoice does repeated O(n) iteration, while quote aggregates once; this is a structural observation, not a profiled bottleneck or grounds for optimization. No execution or profiling was performed.

## Test coverage assessment

Five test methods exist. `create_quote` and `preview_invoice` have direct test calls; `calculate_quote` and `room_subtotal` are reached indirectly by quote tests; `rules.cancellation_fee_due` has one direct boundary test; `pricing.cancellation_fee` has no test call. This establishes static reachability only, not executed line/branch coverage. [All test call sites](04-function-call-graph.md).

Missing test dimensions include multiple lines, explicit `rooms` counts, rounding ties, malformed fields/types, negative and non-finite amounts, one-shot iterators, cross-path equivalence, the approved 48-hour boundary, timezone conversion and the pricing cancellation helper. No coverage percentage can be reported. Historical invoice/rules assertions conflict with approved policy and cannot be treated as acceptance evidence for the intended rule.

## Legacy dependencies and technical debt

No third-party library or version is declared, so there is no evidenced deprecated dependency to report. Historical business logic is demonstrably stale; that is different from library deprecation. Inline policy literals, duplicated algorithms, absent type hints/validators, sparse tests and unconfirmed runtime setup are evidenced maintenance concerns. No architecture rewrite or abstraction is proposed as part of this discovery. See [dependency register](02-module-dependency.md) and [open decisions](08-unknowns-and-validations.md).
